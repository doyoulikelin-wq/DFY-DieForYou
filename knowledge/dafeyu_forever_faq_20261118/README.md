# 大肥鱼 · 魔兽世界无限情境 FAQ 资料库
资料版本：2026.11.18-v1；核对日期：2026-11-18，北京时间。目标游戏：暴雪《魔兽世界》：“无限” / World of Warcraft: Forever，国服优先。

## 交付规模
- 958 张情境卡；1851 种回答表达（包含严格沉默动作）。
- 3127 条编写问法；另有 9255 条标明用途的检索表面变体。合计 12382 条索引记录。
- 181 条官方原子事实；4 条社区问题证据。
- 40 个去重来源/作品组，来自 48 条原始来源记录。其中 29 个官方来源组、11 个公开玩家论坛来源组。
- 18 套四段故事框架；互斥地点展开后 26 张故事交付卡。
- 90 个分类，15 个允许进入主动触发判断的候选。

这些数量分别代表情境、表达、问法、事实和来源；不能相加成“知识条数”。检索表面变体只增加常见呼唤/简答措辞，不是新的游戏事实。

## 从哪里开始
1. 打开 dafeyu_forever_faq.html：离线搜索、分类、查看大肥鱼回答、来源、适用条件、抑制条件和 JSON。支持下载当前筛选结果。
2. 研发接入读取 faq.jsonl、facts.jsonl、sources.json。也可直接导入 faq.sqlite。
3. queries.jsonl 是问题到卡片 ID 的候选召回表。来源事实在 facts.jsonl 只存一份，回答通过 [[fact:ID]] 引用。
4. persona.json / PERSONA.md 是角色行为约束；runtime_policy.json 是建议的运行边界。
5. coverage_gaps.json 列出未完整覆盖的内容；validation.json、retrieval_validation.json 和 browser_validation.json 记录实际完成的检查。
6. content_review.json 包含独立审查意见；最终卡片已采用明确修订，原审查文本是过程记录，不应当作对玩家的回答。

## 她是谁
大肥鱼是一只陪玩家探索艾泽拉斯的虚拟小精灵。好奇、主动，带风象式轻盈与 ENFJ 式热情，也会体贴地退后。性格标签是创作提示，不用来推断玩家。
胜利时可以欢呼，受挫时不强行欢快，讲故事时慢下来。她希望从玩家愿意分享的话里了解现实，以小心、天真、珍惜来表达低姿态，不让玩家承担安抚她的义务。沉默也可以是合适的回应。

## 信息与 Agent 边界
公开网页/论坛仅用于这次离线知识整理。运行时可使用：游戏内部接口、用户文字、显式传入且有出处的已审核知识与记录。没有屏幕、声音、摄像头或现实环境感知。大肥鱼不得声称亲眼看到现实天气，也不能从游戏天气推断玩家窗外。
各 Agent 独立接收信息包，不读取其他 Agent 的记忆。需要的偏好、指代、最近回答、剧情进度和已交付内容都通过字段传递。静态资料资产可以按版本发布给各模块；这不构成共享私人会话记忆。

## 资料可信度
- 官方上线资料：可作为截至发布日期的公开依据；状态变化仍需核对。
- 上线前职业设计：保留预告身份，不能假装当前技能已实现。
- 热修：保留文章更新时间、具体段落日期和地区；标题日期可能落后正文。
- 海外公告：与国服分开，不自动证明国服同步实施。
- 玩家帖子：用于发现困惑、争议和异常；不是某个机制或全服故障的证明。
- 原创陪伴对白：没有外部 source_id 是正常情况；它们不能证明游戏事实。
- 故事：只用已核实的原子事实/用户提供的任务文字。角色观点保留归属，未来时间线不乱接，重剧透要明确许可。

资料来源按同一篇文章或作品合并，避免中文/英文/新闻页/PDF被错误当成独立证据。未转存论坛全文或故事全文。

## 在线快速交付的正确方式
先确认用户意图和当前状态，再检索候选、检查条件、绑定字段并交付。状态未知或矛盾就不直接发。不能仅凭相似度认定答案正确。
required_context / trigger / suppress_when 中部分仍是可读规则，必须由真实游戏适配器映射；它们不是已实现的 Blizzard API 函数。guards 是示例结构，不能从未验证的用户文本里直接填 true。
普通问答不要先调用一个重模型来决定是否使用 FAQ，再调用模型润色；明确命中时可选一个完整表达直接使用。新问题、歧义和复杂规划保留模型路径。
对不同表达分别检查依赖：无名称的安全欢呼不应因缺少首领名称而被一并拦截；包含名称的版本则必须有可靠名称。
“我来讲/我去看”不算完成回答。缺少已整理内容的卡不应被当作已交付；已审核剧情、比较结论、战斗复盘可通过明确槽位填入。
默认不自动启用全部主动卡。主动频率配置是待实测的初始设计值，不是心理学或产品实证结论。

## 重点防错
- 任务窗口、任务ID或费用选项变化后，“点接受”立即失效。
- 技能放不出要区分法力、冷却、目标、距离、视线、控制等原因。
- 有名字不等于首领，不等于敌对怪物；目标消失不等于击败；没有证据不说首杀/单杀/救全队。
- 只允许庆祝已确认的战果；用户说“以后小声庆祝”不代表刚获胜。
- 天气变化不自动写成下雨。
- 记忆/删除/执行的成功要有对应当前请求和最新偏好的回执。
- 用户要求不回复时，允许 delivery_kind=silence 和空字符串。
- 主动探问没有得到回应，不追加追问；沉默不表示同意或满意。
- 用户生活优先，不以她的孤独、伤心或被遗忘来催玩家在线。

## 本地演示与验证
本地候选查询（Python 标准库，无 API Key，无网络）：

    python3 retrieval_demo.py "技能为什么放不出来"

运行示例门控测试：

    python3 validate_retrieval.py

本次示例门控检查：59/59 通过。本机已建索引后的 160 次查询，中位数 0.481 ms，P95 0.706 ms。
这仅测本地字面候选检索，不包括语义意图识别、网络、游戏数据收集、UI显示或模型调用；不是生产环境回答速度。查询探针取自已有或近似问法，不是留出集准确率。门控测试用合成可信状态夹具，不证明真实客户端适配器已经实现。

## 尚未完成的全量覆盖
这版不是完整的无限任务/法术/物品/掉落数据库，不能声称已覆盖游戏中所有情况。全部新旧任务正文与前置、每个NPC、每位首领技能、全部精确掉率和实时拍卖价格仍需继续收集和版本化核验。coverage_gaps.json 给出具体补齐条件。
没有把未知机制改写成自信回答；对应卡会要求当前接口信息或进入核实流程。没有完成真实游戏联调、真实用户自然度盲评或全面人工语义审校。未来版本还会改变公开规则。

## 更新和验收
新来源先建原子事实，标发布日期、适用地区和版本；对影响旧事实的内容建立替代关系。未命中、误命中、重复感、打扰和用户纠错分别记录。离线扩充候选后，使用未参与生成的真实问法与“同问不同状态”反例测试，再发布新版本。
建议衡量：首个有用回应耗时、无需生成的有效交付率、错误命中率、连续会话重复感、主动提问被拒绝后的停止情况。不能用生成条数代替覆盖率，不能用同一模型自评代替全部验收。
